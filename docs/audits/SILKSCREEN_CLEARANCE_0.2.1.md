# Silkscreen Label Placer 0.2.1 clearance validation

20 October 2026. Windows, KiCad 10.0.6 native Python 3.11 and kicad-cli.

## Corrected behavior

- Preview glyphs now use native polygon geometry at board scale, including font,
  stroke, rotation, mirroring and knockout holes. The old wx font imposed a
  minimum screen size larger than the checked text box at some zoom levels.
- Automatic sizing is enabled by default: 1.0 mm preferred, 0.8 mm minimum, with
  the stricter native fabrication floors. Existing oversized text is capped by
  the preferred size in automatic mode. Explicit fixed mode retains its prior
  semantics and can preserve larger existing text.
- Refresh native courtyard caches before planning. Native KiCad can retain a
  stale courtyard after direct edits to its child graphics.
- Reserve courtyard envelopes on both faces, including the label's own part.
  Incomplete courtyard drawings reserve their complete drawn bounds. A footprint
  without a courtyard on its component face uses its conservative body hull.
- Reserve fixed text's native glyph/knockout envelope as well as pads, mask
  openings, same-side silk graphics, proposed text and guides. Guide searches
  include enough outward space for a checked corridor around larger courtyards.
- Apply compares the actual native field/glyph envelope with the reviewed box;
  mismatches roll back. Courtyard/graphic changes invalidate stale previews.

The source file stayed unchanged; analysis and native DRC used disposable copies.
Marble has 51 footprints with courtyard graphics but no usable polygon; these
were reserved conservatively. Opposite-side courtyard handling and stale native
cache behavior were also reproduced independently on synthetic footprints.

The new `help-clearance.png` is a 1200×900 raster generated by the actual preview
drawing method from the synthetic 100-part fixture. It is not a desktop capture,
and contains no personal paths or project data. Earlier UI images are retained.

Existing unrelated/locked/hidden/unresolved labels can still have violations.
They remain unchanged and are not represented as accepted placements. The tool
does not hide references to manufacture a clean board. The Marble DRC baseline
still contains existing silk overlaps and other errors. Rectangular envelopes
can reject arrangements that would fit between individual glyph strokes.
Native Linux/macOS GUI and KiCad 11 remain unverified.
