# Analytics Studio copper workflow — 26 October 2026

Source correction after 3.6.32; existing release binaries are unchanged.
Windows, KiCad 10.0.6/Python 3.11.5; source tests also use Python 3.14.2 and
Shapely 2.1.2. Browser checks use the installed Microsoft Edge.

## User workflow

Copper & routing is a main navigation view, independent of component analytics.
It accepts a saved PCB without a schematic or BOM. Layers, nets, net-by-layer,
individual zones and component pad contact have searchable tables and complete
JSON/HTML or selected-table CSV/TSV exports. The CLI has the same PCB-only path.

An owned child process computes geometry. Cancel, timeout and source changes
reject partial/stale results. The source hash is verified before computation,
after computation and before export. The interface polls without rebuilding the
page on each progress update. Component analytics skips full copper unions;
existing CLI analytics retains its default complete-report behavior.

## Geometry evidence

Polygon unions remove overlapping copper. Supported drill holes are subtracted;
coverage intersects copper with the board outline. Unknown geometry remains
unknown. Saved zone fill is read, never regenerated. Copper totals summed across
layers are distinct from a physical face area or volume.

Twenty focused backend tests pass. New overlap/drill and complex 8,000-vertex
fixtures compare the optimized area arithmetic against full Shapely Boolean
difference within 1e-8 square millimetres. The optimization caches unions and
uses containment/intersection areas instead of repeatedly carving every drill
into each copper polygon; circle resolution is unchanged.

A native-generated fixture with a rotated footprint, NPTH, track and filled zone
matches analytical copper and board areas within 0.002 square millimetres.
Native copper area was 10.1962706973 versus 10 + pi/16; board area was
99.8037293027 versus 100 - pi/16. Original saved bytes were unchanged.

run reached its 240-second worker budget; no partial report was accepted. The
optimized complete CLI produced a fresh report in 59.5746 seconds, exit 0, in
the private KiCad runtime. This is one cold run, not a hardware-independent
performance guarantee. Source SHA-256 before/after was
`482850dbaaef9157e2e98af765a3c0d4d9c9f800daae224a54bf10e0621f52b0`.
