Prepare the board and runtime

  1. Install Quick PI through KiCad Plugin and Content Manager, then restart PCB Editor. QuickTherm and Quick SI are separate plugins; Quick PI bundles the shared kernels it requires and does not require those sibling installations.
  2. Open the intended PCB Editor, refill zones and save. The analysis reads the saved PCB: unsaved routing, changed zone fills and unsaved stackup edits are not part of that snapshot.
  3. In Board Setup, review physical copper thicknesses and stackup. Check net connectivity and plated-hole assumptions. A default via plating value is not a fabrication measurement.
  4. Launch WayriCAD Quick PI from that editor. Confirm the board path shown by the tool. Multiple editor instances must retain their own project context.
  5. Allow the first numerical-runtime preparation to finish. Native KiCad Python, wxPython and the prepared scientific runtime have separate roles. Setup errors identify missing packages or logs; see runtime setup.

For source or wheel CLI use, install into the intended interpreter and check wayricad-pi --help. Source checkout commands can replace wayricad-pi with python -m quick_pi_plugin.cli. GUI use still needs the supported native KiCad environment. Do not install arbitrary packages into another Python and assume the managed worker will use them.

First DC analysis

  1. Choose a net in Setup. Use Find net or Pick net when the name is unfamiliar; inspect the exact full name before running. Net selection isolates the analyzed net rather than adding unrelated nets to the study.
  2. Choose the actual source pad and primary sink pad on that net. Enter source voltage in V and a prescribed load current in A. Start with one load and a manageable net before expanding to a full rail.
  3. Add the source current budget and sink voltage limits if known. Blank source budget means unlimited; zero means no current budget. Blank minimum load voltage defaults to 0 V; blank maximum is unbounded.
  4. Preview. Check extracted copper, selected terminals, layers and drill voids. Do not run against obviously wrong geometry or a missing zone fill.
  5. Leave Automatic mesh on for the first 2.5D attempt. Review Mesh & material, especially plating and fixed copper temperature; then Run.
  6. In Mesh, inspect narrow necks, pad contacts and via lands. In Results, inspect voltage/drop, current density and loss. Read feasibility and conservation findings before interpreting a coloured map.
  7. Refine the mesh and compare terminal drop and local peaks separately. Export the reviewed result, not an earlier view invalidated by later input changes.

This genuine native Marble preview demonstrates geometry and copper-first display; it is not itself a new solved or measured board result.

An illustrative CLI run is:

wayricad-pi C:/Projects/Example/board.kicad_pcb --net VCC --source J1.1 --sink U1.1 --voltage 3.3 --current 1 --auto-mesh --output pi.json --html pi.html

Replace every sample net and pad with exact names from your board. Run the command with just the PCB path to list saved nets, pads and layers first.

Sources, loads and multiple pins

Choose a demand model

DemandMeaningHow to use it
Constant currentPrescribed load A; voltage depends on copper dropMain Load control or Additional sinks. Best starting point for a rail budget.
Constant powerPrescribed load W; current depends on solved load voltageChoose Constant power · W. Use actual delivered load power, not source input power.
Resistive loadPrescribed Ω; solve positive DC current from source and pathChoose Resistive load. Separate single-path workflow.
Current sweepSeveral independent DC operating pointsMore → DC current sweep; 2–200 positive current points. This is not a time waveform.

Additional sinks can mix fixed A and W in the supported fixed-temperature 2.5D workflow. Each demand is a total for its load unit. A source budget is a diagnostic: it does not simulate regulator foldback, current limiting or converter control. INFEASIBLE means the entered current budget or voltage window is not met. The requested-load field can remain useful diagnostically but must not be described as the source's achievable operating point.

Constant-power mode solves a nonlinear high-voltage DC operating point and reports collapse or failed acceptance. It does not enable transient constant-power regulation. Shared-return power coupling, automatic current-based convergence, sweeps, series/package and 3D power combinations retain their stated restrictions. See constant-power details.

Include the other pins deliberately

  1. Select one source or sink pad.
  2. If its owning footprint has eligible pads on the same exact net, review the Include other same-net pins suggestion. It appears only when applicable; pins already reserved for another endpoint are excluded.
  3. Check it only if those contacts represent one intended internal endpoint.
  4. Review the grouped pad list and total A or W before Run. Additional sinks have the same option.

Grouped pads are ideal equipotential contacts. The solver distributes their current according to copper conductance; it does not assign equal current to every pin. Package and internal resistances are absent unless explicitly modeled by a supported contact workflow. Same-net pins on different footprints are not silently combined. Duplicate, overlapping or cross-net contacts fail validation.

For exact grouped current units, use the batch schema and the bundled shared-return example. A supply case can use source_terminals and sink terminals arrays; singular and plural alternatives must not be supplied together.

wayricad-pi C:/Projects/Example/board.kicad_pcb --net VCC --source J1.1 --voltage 3.3 --load U1.1 0.8 --power-load U2.1 1.65 --source-current-limit 2 --load-voltage-limits U1.1 3.1 3.4 --html loads.html --output loads.json

The flat CLI example uses single-pad endpoints. Use JSON for explicitly grouped contacts; repeating a sink pad is not a way to form a group.

Inspect, navigate and change current

Board and results controls

The Net, Mesh and Results tabs share the board canvas. Drag to pan, use the wheel to zoom and double-click or Fit to restore the extent. Setup and Inspect header controls hide side panels; drag the inspector divider and table columns instead of accepting unreadably small panes.

The first multi-layer view selects All copper layers. Silk is a separate toggle, off by default; Board retains outline and holes. Copper and Field independently toggle extracted geometry and results. Only simulated nets limits context; uncheck it deliberately to inspect surrounding copper. An all-layer projection can make local picking ambiguous: choose a physical layer for exact inspection.

Select a result quantity and read its unit/colour legend. Hover to inspect solved cells; click to pin and Ctrl-right-click to clear point probes. Losses and Probe tables sort by column and cross-select supported cells, layers and barrels. Exact saved object identity is needed for selection in the originating PCB Editor; an approximate visual location is not proof of an editable native match.

V1, V2… identify extracted physical vias in board-coordinate order. Axial segments share that physical via ID and show their layer span. C1, C2… are mesh-cell IDs. Original native UUIDs remain in evidence; cell numbering can change after remeshing.

Tune prescribed currents with Ctrl+scroll

After an eligible fixed-temperature 2.5D constant-current solve, leave Ctrl+scroll load enabled. Plain scroll zooms. Ctrl+scroll near a sink pad or marker changes only that load unit; all grouped pads control the same total. Near a source marker, or elsewhere on solved copper, it scales the total and preserves load proportions. Nearby ambiguous markers consume the gesture without changing a load: zoom, choose a layer or move closer to the intended sink.

Slow scrolling gives fine increments; faster scrolling gives coarser increments. Base step · A sets the normal step. A pause or reversal restarts fine adjustment. Enable Cursor preview and choose Selected metric or All metrics to compare the old/new current and signed field change near the pointer. Increase/decrease colours are not pass/fail indicators. Wait for pending work before export.

Proportional updates reuse the linear field: drop and J scale with I, loss with I². An independent sink change needs a new fixed-mesh electrical solve, so its first update can take longer. This control is unavailable for power loads, resistive loads, series/package paths, 3D and temperature-feedback studies.

Differential voltage probes

In Inspect → Probe select Set probe A, click solved sheet copper and click B. Orange A and blue B markers show the positions. Read signed V(A) − V(B); Clear A/B returns to single-point inspection. Both points must share one solved case's potential reference. Independent case voltages cannot be subtracted merely because their plots look alike.

The image is a computed analytical strip fixture, not a measured board. Sampling uses finite-element nodal potential within the containing triangle. Holes, missing nodes, unsupported full-volume points and barrel interiors remain unknown. In all-layer projection select the physical layers explicitly.

python -m quick_pi_plugin.cli --probe-result pi.json --probe-a 0 2 0.5 --probe-b 0 8 0.5 --output differential.json

Use actual saved mesh layer IDs and solved coordinates. This reads a saved result without a new solve. The HTML report retains saved probe values; reports up to 20,000 triangles also provide a separate click-to-pick A/B map.

Mesh sizing and convergence

Automatic mesh recommends a background size from occupied copper extent and grades refinement near supported tracks, pad contacts and barrel lands. It is a geometry heuristic, not an error estimator. Curved paths, narrow zone necks and contact peaks can still need manual examination. A hard budget stops the run; the tool does not silently discard a fine feature to make the run finish.

  1. Preview copper and inspect the recommendation.
  2. Solve a manageable first mesh.
  3. Use Refine or More → Check mesh convergence. Refinement uses a fixed background followed by manual halving, rather than repeating the same automatic mesh.
  4. Compare terminal drop, sheet/barrel losses and local J peaks independently.
  5. Keep unresolved sensitivity in the report. Stable terminal resistance does not establish converged local hotspots.

CLI alternatives are --auto-mesh or --mesh-edge 0.2 in mm, never both. Add --mesh-only to inspect a mesh without solving. --mesh-backend auto uses Gmsh when available or the VTK alternative; explicit gmsh/vtk requires that backend. Default 2.5D budget is 400,000 triangles. --max-cells accepts 1,000–2,000,000 for supported ordinary 2.5D cases; a larger budget can require several GB of memory. Do not increase it automatically without reviewing available memory and scope.

wayricad-pi C:/Projects/Example/board.kicad_pcb --net VCC --source J1.1 --sink U1.1 --current 1 --voltage 3.3 --mesh-edge 0.4 --converge-levels 4 --convergence-tolerance-percent 1 --html convergence.html --output convergence.json

Three to five levels are supported. Both final refinement changes must meet the selected criterion. Local peak and physical-model acceptance still require review.

Multiple rails and ground returns

Independent rails

  1. Configure a rail in the main window.
  2. Open Rails / ground returns and Add net case for each additional rail.
  3. Review each source, load unit, voltage, mesh and current/voltage limits.
  4. Run the study and read every case status, including failures. Cases are independent until explicitly linked by shared return mapping.

Batch studies contain 1–32 cases bound to one saved PCB hash. Start from batch rails, replacing illustrative names and numbers. Source or study changes invalidate the batch.

Shared ground conduction

  1. In Rails and returns, select the participating fixed-current rails and choose Set up ground / return.
  2. Select the real return net, supply-ground source pads and each load-ground pad unit. Suggest matching footprint pads is a proposal, not an inferred loop.
  3. Review every mapping and Apply return setup. All loads of each participating case need exactly one mapping.
  4. Run. Review physical ground rise, delivered load voltage, shared loss and source/load/copper conservation.

One shared-return group solves its return copper once with every mapped current. Changing one rail can change another rail's ground rise. Multiple groups cannot reuse a case. Return loss is counted once, not once per rail. Shared groups do not support constant-power regulation, series/package branches, 3D loops or combined loop temperature feedback. The legacy single-load return_conduction schema remains available; new grouped studies should use shared_returns.

wayricad-pi C:/Projects/Example/board.kicad_pcb --batch reviewed-rails.json --output rails.json --html rails.html

Reference-plane and via audit

The Return path tab answers a different question. Choose signal and return nets, then Review return path. More return options contains multi-return selection, optional pads and sampling. Refill and save first. Inspect adjacent filled-plane coverage, gaps and return vias near evidenced transitions. A clear sampled route does not prove electrical closure, loop inductance or controlled impedance.

wayricad-pi C:/Projects/Example/board.kicad_pcb --return-path --net VCC --return-nets GND --return-pitch 0.25 --return-via-radius 2 --html return-review.html

See return audit method for geometry support and evidence limits.

Series components and parallel parts

Use Build series path to represent an actual path crossing nets through explicit two-pad components. Choose source and sink pads, add compatible parts in order and review the model value for every stage. Use KiCad selected pads/components only after confirming which originating editor supplied them.

Parallel parts finds two-pad parts across the same exact saved net pair, including reversed pin order. Check only intended branches and verify each R/L model; resistor values may be suggestions, but unknown DCR is not invented. Highlight included parts before running. Save the reviewed path JSON for reuse.

Console commands run the same bounded worker, not a Python shell. Expand Console; use help, nets, pads NET, Tab completion and Up/Down history. Quote net names containing spaces. An illustrative series path is:

run pi C1.1 R1.1 5m R1.2 L1.1 5mH+30m L1.2 U8.2

This declares 5 mΩ and 5 mH + 30 mΩ, not automatically measured components. Inductance adds no steady-state DC drop; it contributes stored-energy reporting. Fixed-drop and forward diode models are also explicit DC operating-point models, not switching or reverse-bias simulation. Additional sinks and explicit series paths cannot be silently combined. Syntax and diode restrictions.

wayricad-pi C:/Projects/Example/board.kicad_pcb --series-file reviewed-path.json --voltage 3.3 --current 2 --html series.html --output series.json

Package contacts and full-volume copper

Finite lead, solder and BGA contact paths

Package contacts adds reviewed one-dimensional resistance paths between a package port and specific board pad faces. Declare geometry, material resistivity and attachment layer; use explicit interface resistance where justified. No package dimensions or material values are inferred. Review current sharing and separate sheet, barrel, package and component losses.

Use --package-conduction contacts.json only in the supported constant-current 2.5D workflow. It is not a 3D solder field or reliability model. Series paths, resistive loads, sweeps, 3D, rail transients and electrothermal modes reject these contacts. Contact schema and example.

Full-volume 3D DC copper

Choose Copper model → 3D · copper volume (Gmsh), select source/sink and a specified current, then set a manual mesh and tetrahedron budget. Gmsh is required; first setup may need package access. Preview before Run 3D copper. Inspect layer/barrel filters, voltage, current-density and volumetric-loss fields. Orbit, pan, wheel zoom and sampled-cell probes affect only the view. Exports retain complete numerical fields even when the display samples for speed.

wayricad-pi C:/Projects/Example/board.kicad_pcb --net VCC --source J1.1 --sink U1.1 --voltage 3.3 --current 1 --model-dimension 3d --mesh-edge 0.25 --max-tetrahedra 250000 --output pi-3d.json --html pi-3d.html

The model uses saved layer positions, copper solids and supported circular through-hole plating. Plated slots, backdrills and unresolved drill contours are unsupported in this volume mode. It is fixed-temperature DC, with no AC skin, displacement current, series components or thermal feedback. Automatic volumetric mesh sizing and the 2.5D melting screen are unavailable. Review volume and conservation checks and refine before relying on local peaks.

Copper heating and bottlenecks

Ordinary DC already computes I²R loss. It separates sheet, via barrel and explicit component/contact losses. Delivered load power is not automatically board heat.

After a 2.5D solve, choose Inspect → Copper melting bottlenecks or the Pulse / adiabatic melting action map. Enter Pulse · s, initial/ambient temperature, melting temperature and latent heat under Mesh & material. Review the actual material assumptions; defaults are explicit modeling assumptions. Select rows to focus solved cells/barrels and exact native objects where available. B1–B6 mark the leading ranked regions; Vn continues to identify a physical via.

The screen estimates local adiabatic melting action with a frozen DC field. It omits cooling, changing current sharing, molten geometry, arcing and circuit interruption. Long predicted times are especially sensitive to those omissions. Ranking is current-density-based with spatial suppression, not a guaranteed geometric minimum-cut detector. Mesh/contact peaks can dominate. Melting onset is not fuse opening, protection coordination or safe ampacity.

wayricad-pi C:/Projects/Example/board.kicad_pcb --net VCC --source J1.1 --sink U1.1 --voltage 3.3 --current 2 --pulse 0.01 --ambient 25 --melting-temperature 1084.62 --latent-heat 206750 --output pulse.json --html pulse.html

See material integral, validity and references.

Joule temperature feedback

Check Include Joule heating / temperature feedback only after reviewing the thermal model. This adds steady temperature-dependent resistance iteration; it does not enable or disable ordinary DC loss accounting.

  1. Enter thermal conductivity, cooling, emissivity, ambient, allowed material range and temperature cap. Review copper resistivity and its temperature coefficient. Required unknown values block the run.
  2. Review where electrical copper losses enter the shared thermal layer model. Do not add delivered load power as board heat without a separate justified component dissipation source.
  3. Run and inspect temperature, resistance/voltage change, iteration history, energy transfer and acceptance. Nonconvergence is not a valid final operating temperature.
  4. Refine spatial and iteration settings as appropriate and retain cold/hot evidence in the report.

More → Electrothermal study also offers explicit lumped rail/thermal-RC transients. These are separate from spatial full-board transient fields. Finite-contact temperature feedback and individual shunt-bank electrothermal stepping remain unsupported. See complete input, example and CLI guide.

wayricad-pi C:/Projects/Example/board.kicad_pcb --electrothermal reviewed-electrothermal.json --output electrothermal.json --html electrothermal.html

AC and switching-ripple losses

  1. Open More → AC / SMPS copper study.
  2. Enter section length, DC current, copper temperature and optional rail voltage. Rail voltage supplies context, not insulation qualification.
  3. Choose a balanced quick-loop preset and enter outgoing/return dimensions and spacing. Inspect the live cross-section. Run uses the visible quick recipe; no separate Apply action is required in 3.6.40.
  4. Enter ripple frequency and RMS current. Peak and peak-to-peak current are not RMS; use Build SMPS waveform for the supported triangular or pulse helper, or enter a reviewed harmonic table in Custom mode.
  5. Expand Custom tables for multiple conductors/harmonics. Use +1/−1 current scales for a simple outgoing/return pair. A split return is a user assumption, not automatic current sharing between arbitrary board paths.
  6. Run AC / ripple losses. Inspect total copper heat, ripple heat, loop RMS drop and combined RMS current. Use Inspect to choose harmonic heating, impedance or cross-section. Select table rows or hover/click plots for exact values.
  7. Read Checks / applicability, mesh and boundary refinement before exporting.

These genuine native captures use an explicit illustrative copper pair, not automatically extracted PCB geometry. Capture inputs and checks.

AC inputs use mm, Hz, A, V and °C; tables display engineering units. JSON geometry uses cross-section centre x/y, width along x and thickness along y. Include every modeled return. Skin/proximity redistribution is solved in the straight uniform section; changing its length is not equivalent to importing a routed board.

Mesh and magnetic-domain refinement compare impedance independently. UNCONVERGED values are provisional. Local J peaks can remain sensitive even when port values settle. Supported temperature, harmonic count, budget and electrically-short limits are checked. No converter control, dielectric field, HV spacing or whole-board AC/thermal qualification is implied. Fixed-temperature harmonic losses are not automatically injected into the saved-board DC temperature iteration.

wayricad-pi --ac reviewed-ac.json --output ac-result.json --html ac-report.html

Start from the illustrative SMPS input, then use AC method and limits and setup help.

Decoupling placement and PDN impedance

Placement proximity review

Open Decoupling placement, set rail/ground patterns, load-reference patterns and maximum capacitor-pad distance, then Analyze PDN. Review qualified rail-to-return capacitors, failed/warning pins and the linked placement map. Double-click a row to locate its component and export CSV. Reload saved board after refill/save. This does not move parts or predict electrical impedance from proximity.

Lumped impedance screen

  1. Open Decoupling → Lumped impedance screen.
  2. Enter allowable ripple in mV and current step in A: target impedance is ΔV/ΔI.
  3. Enter source R in mΩ and total source/loop L in nH.
  4. Add effective C in µF, ESR in mΩ, part-plus-mounting ESL in nH and parallel quantity. Include known bias, temperature and tolerance effects in effective C.
  5. Choose a frequency band and Calculate. Inspect magnitude, phase, sampled peak, resonance/antiresonance and doubled-grid changes; hover or click to probe.
  6. Export sampled curves or save the explicit model. Keep model inputs with the result rather than treating a screenshot as complete evidence.

The network is source R/L in parallel with series C/ESR/ESL branches relative to the ideal source AC ground. Resonance-aware sampling helps but cannot prove that every narrow peak was found. SAMPLED_TARGET_MET applies to the explicit sampled network only. Placement extraction, regulator control, distributed plane effects and automatic capacitor derating are absent. PDN model and checks.

Load-step and shunt-capacitor transients

  1. Open More → Transient load-step study. Review imported sink names, final demands and voltage bounds; they are starting inputs, not an extracted transient model.
  2. Enter shared source R/L, each branch R/L, effective load C and ESR, before/after current and event time. Use a finite load-current rise where physically needed. Quick fields use displayed engineering units; Advanced SI editor uses Ω/H/F/s.
  3. If a matching single feasible copper path seeds total R, inspect that mapping and do not count it again in branch resistance. L and C are explicit; a DC mesh does not supply them automatically.
  4. For separate bypass/filter parts, select the load and Shunt capacitors for selected load. Enter each effective C, ESR and total part + connection ESL. The bank replaces that load's aggregate C/ESR, preventing double counting.
  5. To review saved-board candidates, choose the actual return net. Only exact two-pad rail/return C-reference candidates qualify. Unit-bearing values may prefill; ambiguous codes and unknown parasitics are not guessed. Include each part deliberately. Bulk ESR/ESL edits apply to checked capacitor rows.
  6. Set duration, time step and bounds. Recommend time step gives advice, not a convergence certificate. Run transient, then inspect voltage, source current, checks and individual Capacitor response traces.
  7. Refine the time step and compare waveform and half-step evidence. Save explicit inputs and export HTML/JSON together.

These are genuine captures of the explicit shunt example. The illustrative 3.3 V network is not a measured PCB or regulator model.

The model begins at pre-step DC equilibrium and advances an explicit lumped rail network. Source current budget violations are diagnostics, not simulated current limiting. Finite-rise events are prescribed, not switching-device dynamics. An ideal step requiring an impulse in an all-inductive cutset is rejected; use a physically supported rise time. Review charge, energy and half-step checks. The bank supports at most 128 total aggregate/shunt branches within bounded time/trace budgets; oversized work is rejected rather than silently truncated.

wayricad-pi --transient reviewed-transient.json --output transient-result.json --html transient-report.html

An optional positional PCB binds source provenance but does not extract the circuit R/L/C. JSON uses F, Ω, H and s; bank IDs must be globally unique. Current shunt-bank transients do not include constant-power control, arbitrary distributed capacitor positions or coupled electrothermal stepping. Time setup guide.

Reports and automation

Save an engineering review

Export from the study that produced the current result. Native Export creates offline HTML and paired JSON with source custody, inputs, fields and checks. Choose distinct HTML, paired JSON and explicit JSON output paths. Keep batch case-report folders beside their complete parent JSON: lightweight child JSON descriptors refer into that archive rather than duplicating every array.

Reports include voltage/drop, J and loss maps. Large planar models use three primary static figures to control cost; numerical cells remain in evidence. Interactive fields are retained where supported. The Power flow Sankey goes from source power to delivered load power and modeled losses. Shared return loss is counted once; unsupported or inconsistent accounting reports unavailable instead of inventing a balance. It is a power budget, not spatial current streamlines.

For native 3D reports, drag to orbit, Shift-drag to pan and wheel to zoom. Saved views and probes do not modify the PCB. HTML is the interactive deliverable; static PDF cannot retain browser interaction or every canvas/SVG view.

Use Print / save as PDF, or install the reports extra in the exporting interpreter and run:

python -m wayricad_runtime.tool_cli report-pdf pi.html --output pi.pdf --evidence pi.json
python -m wayricad_runtime.tool_cli report transient-result.json --html review.html --pdf review.pdf

Direct PDF retains text, tables and embedded PNG/JPEG figures. Unsupported interactive-only views are listed. Raw JSON is a closed evidence disclosure in HTML and summarized in PDF by default. --include-raw-evidence requests raw evidence in PDF when needed. Generic saved-JSON export creates readable tables; it does not rerun the original study or reconstruct missing fields. Shared report guide.

CLI and jobsets

Use wayricad-pi --help for the actual installed parser. Named JSON modes use their own schema and restricted flag combinations; do not append ordinary DC flags expecting them to override a different study. --timeout bounds worker time. --verify runs the analytical reference suite, not your board.

ExitMeaning
0Completed accepted calculation for the selected workflow; not general physical qualification.
2Invalid inputs, unsupported combination, execution or publication error.
3Incomplete/review-needed or unstable/nonconverged study, depending on mode.
4Entered load/source or operating limits violated; not an automatically corrected design.

Saved differential probing returns 3 when not sampled and 2 for invalid input. Batch results retain per-case failure status; inspect those rows even when some rails succeeded. Preserve input JSON, full output, logs and report together.

Use the shared report runner and native KiCad jobset integration for ordered PI/SI/Therm steps, logs and a report index. It calls the same CLI, so required inputs, rejection rules and solver limits still apply. Jobset setup and examples.

Troubleshooting and acceptance

SymptomAction
Copper missing or wrong boardConfirm originating editor, refill/save, then More → Reload saved board. Unsaved changes are not the saved snapshot.
Only silk or clutter visibleUpdate/restart, select All copper layers, turn Copper on and Silk off. Check Only simulated nets and physical-layer filtering.
No matching terminal or disconnected copperInspect exact net/pad names, actual connectivity and filled zones. A name match alone is not a connected copper path.
PCB changed since analysisSave the intended revision, reload and rerun. Do not bypass source checks to export an old result as current.
Missing runtime/dependencyRead the setup log and use the intended managed/native interpreter; check allowed package source or configured offline wheels.
Memory, budget or timeoutStart with fewer cases/a smaller net or reviewed coarser mesh, then refine. Increase explicit budgets only when memory permits.
Current wheel does nothingConfirm fixed-temperature constant-current 2.5D mode, enabled control and unambiguous marker/layer; unsupported modes require Run.
Probe unknownChoose actual solved sheet copper on a physical layer; holes, gaps, unknown nodes and unsupported dimensions remain unknown.
Result INFEASIBLEReview load units, source budget and delivered voltage. Do not describe requested-load diagnostics as a sustainable source operating point.
AC UNCONVERGED or transient large half-step changeRefine numerical settings within applicability/budgets and inspect inputs. A coloured plot is not acceptance evidence.
Current-density peak keeps increasingExamine contact/corner singularity and mesh sensitivity separately from terminal drop; retain unresolved status.
Sankey unavailableRead missing/inconsistent power evidence. Do not force balance by hiding losses or counting delivered watts as copper heat.

Before accepting a study, confirm source revision, geometry, units, demand and return assumptions; read all unknown/incomplete cases; inspect conservation; perform relevant mesh/time refinement; and compare against measured or independent reference evidence where required. Successful execution and attractive plots establish neither hardware safety nor manufacturing acceptance.

Methods and references

The layered model solves conductivity with finite-element potentials and axial barrel paths; 3D uses tetrahedral conductivity FEM. AC uses its explicit local A–V cross-section formulation. Transients use explicit lumped circuit equations and numerical time/conservation checks. These are different models and should not be described as one full-board electromagnetic simulation.

Blender visualization

This feature is in the updated source; existing 3.6.40 installers do not contain it.

After a supported completed study, choose Blender… in the main result workspace. Choose a new output folder and optionally open an installed Blender. The export includes geometry, available field data and supported computed frames. Export saved transient or other supported results through the shared CLI when they are not the main workspace result. Review the Blender walkthrough for commands, units, playback, result coverage and limits. This is visualization, not an additional numerical solve.
