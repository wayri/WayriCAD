Fabrication Net Comparison

Introduced in 4.8.3. Verification covers the supplied endpoint partitions and source identities, not vendor-CAM qualification or physical fabrication approval.

Imported netlist comparison, not physical fabrication approval. No Gerber copper reconstruction or PCB editing occurs. MATCH means matching supplied endpoint partitions only; fabrication_verified stays false.

Compare Saved Inputs

With saved PCB context, Export design reference... runs the native helper asynchronously on a private copy. Choose a new .d356 path; a .d356.receipt.json accompanies it and the reference picker is filled. This is design-netlist evidence, not independent CAM extraction. A completed new output just before cancellation is retained for inspection.

The summary shows reference binding separately. A present native receipt must match the reference and supplied saved PCB hashes; the receipt itself is source-guarded. With no receipt the binding is UNVERIFIED, not an implied match to the active board. Local hash correspondence does not authenticate CAM independence.

  1. Choose a design-reference netlist and a separate observed CAM netlist for the same revision.
  2. Confirm independent CAM extraction only after reviewing its producer and extraction basis. A KiCad reference export is design-netlist evidence, not CAM extraction.
  3. Compare, inspect group counts and endpoint coverage, then select rows for full original net names and pin maps. Sorting preserves finding identity.
  4. Export JSON, HTML, CSV or TXT. Changed sources or controls require a new comparison.

Comparison runs in one background worker. Cancel, input edits and window closing discard late results. An active parser/comparator call cannot be interrupted; cancellation takes effect between calls.

The native table displays up to 5,000 finding rows and selected detail text up to 500,000 characters. Truncation is disclosed; complete findings and original pin maps remain in the canonical report and exports.

Read The Verdict

ResultMeaning
SHORTOne CAM partition joins multiple design nets. One group retains all member nets/pins, not an all-pairs list.
OPENOne design net splits across observed groups.
MISSING / EXTRA / ISSUECoverage, unsupported data or ambiguity needs review. These counts are separate from short/open group totals.
FAILA difference is proven on shared accepted endpoints.
UNKNOWNIncomplete data, unsupported constructs, self-comparison or unconfirmed independence prevents MATCH.
MATCHComplete accepted endpoint partitions match with reviewed independence. Not a manufacturing release.

Exact case-sensitive reference/pin identities establish correspondence, not global net names such as GND or guessed coordinate proximity. Renumbered observed nets may still match their actual endpoint partitions.

Input Limits

The bounded core accepts normalized wayricad.fab-netlist/v1 JSON or a conservative IPC-D-356 317/327/367 subset with explicit CODE 00 and CUST 0 units. Unsupported units, transformations and ambiguous/truncated identities cannot establish a complete match. Mechanical/via records are not proof of full component-pin or copper coverage. Netlists are limited to 16 MiB plus bounded records/trees.

Canonical Evidence And Exports

Source SHA-256, byte counts, modification timestamps and report SHA-256 bind the saved inputs to the result. The core's original group/pin maps remain intact. Export guards protect source/board aliases and publish atomically. HTML treats labels as inert text; CSV prefixes spreadsheet formula triggers. JSON retains exact original values. Local reports may contain proprietary nets, pins and source paths.
