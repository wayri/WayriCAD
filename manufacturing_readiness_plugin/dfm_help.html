DFM / DFA Studio

Screen saved PCB geometry against an exact supplier process, inspect native findings and retain unresolved manufacturing and assembly review requirements.

1. Process | 2. Check | 3. Review | 4. Report | Troubleshooting | CLI guide

1. Select and Confirm the Process

  1. Save the PCB and matching project in KiCad.
  2. Open DFM / DFA Studio from PCB Editor, or DFM / DFA and vendors in Manufacturing Readiness Manager.
  3. Open Vendors. Search supplier/service/material; the process tab initially filters presets by this board's layer count. The directory tab also lists suppliers without numerical coverage.
  4. Select the exact process, read its limits/source dates and choose Use selected process. Multiple services from one supplier are not interchangeable.
  5. Review copper weight, copper basis, inner copper, layers, material, thickness and finish. Dropdowns show the profile's supported values. Disabled fields are not specified by that profile.
  6. Check the process confirmation box only after comparing the actual quote and board. Inspect Rule preview for compiled and omitted rules.

The library includes 24 presets and 28 suppliers. The three added OSH Park presets cover 4 layers, 6 layers and 2 oz/0.8 mm. Other vendors retain their recorded source dates. Public capabilities are conditional, not certification.

Custom profiles: import a bounded, validated vendor-profile JSON with a new ID in the library. Export the selected profile for editing/review. Imports are session-local; save a checklist to retain the complete custom profile, process and evidence. Bundled identifiers cannot be overwritten.

2. Run Checks

Run vendor DRC / DFM checks copies saved PCB/project/rule bytes to a private temporary directory. It enables relevant check providers and clears exclusions only in that copy. The original project custom rules are replaced there by reviewed vendor rules; ordinary project DRC is still required. Manual-only profiles instead run saved project DRC and leave vendor requirements manual/unknown. No copper, zones, footprints or source files are edited.

Cancel stops the owned CLI. A rerun clears old results first. Inputs changed during a run invalidate its result. Optional checks after saved changes do not observe unsaved editor changes. A native check failure is distinct from a PCB with design violations: the latter retains inspectable evidence.

3. Inspect and Resolve Findings

Filter by family/status or search references, nets and descriptions. Click a column header to sort; each row keeps its linked object identity. Select a row to see source references, dimensions and suggested corrective actions. Click Focus for its geometry; wheel zooms, middle-drag pans, and Fit resets the board view. Select a copper layer to isolate it.

Cross-probe in PCB, or double-click a row, selects its saved object UUIDs in the originating editor when the integration is available and the saved source hash still matches. A broad manual requirement may have no objects to select. Cross-probing is navigation, not geometric acceptance.

StatusMeaning
PASSAn individual supported compiled rule passed its narrow check.
FAIL / WARNInspect the actual native finding and rule severity. Correct geometry or record justified review evidence.
UNKNOWNMissing, omitted, unsupported, stale or manual coverage. Not a pass.
N/ANo applicable objects for this specific check; not blanket approval.

Courtyard, mask bridge, silkscreen and dangling-routing findings populate related engineering review items with partial negative evidence. No finding does not establish body clearance, pick-and-place access, stencil quality, reflow suitability, variant/BOM correctness or electrical fitness. Native straight-track arrows show width; marker spacing is not measured clearance.

4. Retain Evidence

Save/load the complete checklist; attach manual evidence and source-bound waivers without rewriting measured status. Export HTML or PDF plus JSON with all checks, even when the table is filtered. Reports include process selections, timestamps and SHA-256 revision identities. A preview failure is disclosed and does not erase completed CLI evidence; the report then omits the board image.

Use the separate Manufacturing Readiness Manager to capture a release snapshot, pass project DRC/jobset checks and create a verified deterministic release ZIP. DFM screening alone does not authorize fabrication.

Troubleshooting and Limits

ProblemResolution
Process scope incompatibleChoose an explicitly supported service/layer/copper/material option. Do not coerce unsupported scope to run.
CLI unavailable or exits unexpectedlyUse the matching KiCad installation. Confirm that the saved board is supported and inspect custom-rule syntax and reported diagnostics.
Checks completed, preview unavailableNumerical/native evidence is retained. Check native helper compatibility; do not interpret a missing image as a clean design.
Stale or discarded resultSave all design changes and rerun. Source/project/rules/profile/context changes invalidate evidence.
Supplier absent or no presetRequest official process limits and import a reviewed custom profile. Directory presence does not invent numerical rules.
Unresolved DFA checksReview actual assembly drawings, BOM/variants, stencil, access, polarity and supplier requirements; attach evidence explicitly.

Native KiCad 10.0.6 recovery and saved-board tests are recorded for 4.8.2. They do not establish all editor/OS/version compatibility or fabrication approval. Read coverage and model limitations, the plugin guide and headless usage.
