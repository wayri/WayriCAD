WayriCAD Trace Refiner

Review and remove small routing jogs and redundant straight segments in KiCad 10.

Trace Refiner adjusts existing straight tracks. Preview shows a proposal; native connectivity and DRC must approve it before Apply. It does not route missing connections, tune lengths or establish signal integrity.

Window workflow

  1. Prepare the saved project. Refill zones, save the PCB and save Board Setup/project settings. Validation needs the matching .kicad_pro and, when present, .kicad_dru.
  2. Choose a small scope. Start with selected tracks or one net. Restrict copper layers if useful. Add all tuned or critical net names to Protected nets.
  3. Set geometric bounds. Displacement and shortening are in mm; both default to 0.10 mm. They must be greater than zero and at most 1 mm. These values are separate from copper clearance and timing requirements.
  4. Preview. Amber is original routing, teal is the proposed replacement and grey is surrounding copper. Wheel zooms, dragging pans and double-click fits. Inspect each affected area.
  5. Validate candidate. A separate native Python worker checks source/rule identity, terminal connectivity and before/after KiCad DRC. Validation can be cancelled and has a six-minute timeout. A failed, cancelled or crashed worker leaves Apply blocked.
  6. Apply refinement. Only reviewed chains are replaced. Inspect the board, refill zones and run final DRC before saving. Undo/Redo is available in this window while the board remains in the expected state.

Closing this window discards its operation history. Ordinary PCB Editor Undo is not claimed. Keep a saved reference for comparison beyond this session.

Scope and geometric bounds

ScopeIncluded routing
Selected tracksSelected straight tracks. Selection boundaries remain fixed.
Selected netsNets of selected tracks, vias, pads or footprints.
Whole boardAll eligible straight tracks on permitted copper layers.
Net filtersChecked exact net names. Searching narrows the displayed list while retaining checked choices.
Net groupsChecked native net classes, rather than KiCad component groups.

Layer filters apply to every scope. No checked layers means all enabled copper layers. Checklist names are literal, including bus brackets such as DATA[0]; protected-net entries use comma-separated wildcards.

Maximum displacement bounds centreline distance in both directions. Every original portion must remain near the replacement and every replacement portion near the original. The complete candidate is checked again after rounding to KiCad coordinates. A 0.03 mm jog can fit a 0.05 mm bound, whereas a 0.005 mm bound preserves it. Larger settings permit more movement but do not guarantee a proposal.

Maximum shortening / chain bounds total length removed from each connected eligible chain, including all its local cleanup windows. It is an absolute distance, not a percentage or board-wide allowance. Independent chains can each shorten by up to the setting. Replacements do not deliberately add length; numerical equality uses a sub-nanometre tolerance.

A chain has the same net, layer and width. Small local windows can become a straight segment or a single bend with horizontal, vertical or 45-degree legs. Larger necessary turns remain. Exact collinear subdivisions may disappear without visible displacement. Eligible chains up to 2,048 segments are supported. Exact collinear fragmentation is collapsed before local window search; longer chains, loops and exhausted budgets remain unchanged. Mask-opening and local mask-margin changes are chain boundaries.

An empty preview is valid: the route may already be simple, protected, outside scope or beyond the bounded geometry proof. Preservation notices describe encountered conditions; they do not count every excluded track. Changing controls clears the preview. Geometry, relevant selection, live rule dimensions/net classes or saved rule changes invalidate source-bound operations.

Review individual proposals

The table lists original/proposed lengths, shortening in mm and segment counts. Click a proposed row to focus and highlight it in the cached viewport without changing PCB selection. Hover for full net names and preservation reasons. Multi-select proposal rows and click Exclude selected to retain their original copper. Preserved notices are not proposals. Every subset edit clears validation evidence and disables Apply; validate the retained subset again. Excluding everything produces an empty preview and no edits.

Native validation is bound to exact geometry/settings. A modified proposal, replacement object or originating board cannot reuse approval. Native calls that mutate and then fail are recovered against their pre-write membership, or explicitly report a recovery failure.

Protected routing and limits

  • Endpoints, pad/via contacts, branches, net ownership, width boundaries and copper layers are retained.
  • Locked/grouped tracks, vias, arcs and repeated tuning meanders are preserved.
  • Names ending in _P, _N, + or -, and discovered P/N counterparts including numbered names, are protected. Default wildcards cover common clock, DDR, USB, PCIe, LVDS, RF and CAN names.
  • Names cannot encode all intent. Add every other tuned or critical net to protection, even when selecting it explicitly.
  • Saved custom length, skew and differential-pair gap/uncoupled constraints remain protected in this version. Use native routing/tuning for constrained boards.

There is no shove routing, via movement, pair retuning or clearance relaxation. Geometric similarity does not establish timing, impedance, reference-plane continuity, fabrication acceptance or electrical performance. Necessary detours remain when no accepted cleanup exists.

What validation establishes

The live board is serialized for a disposable worker. Matching saved project/rule files accompany the snapshots. Live scalar Board Setup dimensions and effective net classes are compared with the saved context; save intended settings before validating. Source/rule identity is checked again before acceptance and Apply.

Native pad/via/zone connected-component membership must remain unchanged. Baseline and candidate DRC runs refill zones. Core copper collision/dimension checks are enabled in disposable project copies even if disabled in saved settings; the source project remains unchanged.

  • A proposed chain with baseline DRC findings blocks the batch. Restrict scope to clean routing or fix the original findings.
  • New DRC or unconnected-item findings block acceptance. Equal report totals alone are insufficient.
  • A baseline with 199 or more findings of any one type is conservatively rejected because native report limits/order can prevent a reliable comparison.

These are acceptance gates for reviewed geometry and saved rule context, not general board qualification. Inspect the final board and rerun native DRC after zone refill. Windows/KiCad 10.0.6 is the native validation target; Linux/macOS GUI and KiCad 11 remain unverified.

Command-line review and export

Run the module with KiCad's native Python supplying pcbnew, from the source checkout or an environment containing the package. It reads the saved PCB and excludes unsaved editor changes. PCM installation does not create a system-wide console command.

python -m trace_refiner_plugin C:/Projects/Example/board.kicad_pcb --net SIGNAL --layer F.Cu --report C:/Projects/Example/review.json

The default operation prints a JSON preview to stdout; --report FILE also saves it to a new file; existing reports are not overwritten. A preview report is not DRC approval. Add --validate to check the proposal without writing a PCB:

python -m trace_refiner_plugin C:/Projects/Example/board.kicad_pcb --net SIGNAL --validate

Export requires successful validation and a new destination. Create the destination directory before running:

python -m trace_refiner_plugin C:/Projects/Example/board.kicad_pcb --net SIGNAL --output C:/Projects/Example/review/refined.kicad_pcb

The source files remain unchanged. Matching project/custom-rule copies use the new board stem; existing output files are not overwritten. Open the exported project, inspect it, refill zones and run final DRC before adopting it. CLI export has no in-window Undo history.

ArgumentPurpose

--helpShow installed usage.

Choose one selector family: net, net class or track. Do not combine families; repeat values within one family. With no selector, eligible whole-board routing is considered. Layers and protection apply in every scope. Differential-pair protection still applies to explicitly selected items.

The installed wayricad-trace-refiner entry point accepts the same arguments in an environment with native KiCad bindings. Validation/export requires the matching saved .kicad_pro, optional .kicad_dru and matching kicad-cli. See the README for a Windows native-Python invocation and installation.

Failure remedies

SymptomNext action
No proposalsCheck scope, selection, layer names and protection. Try one known small jog; already-simple or complex protected routing may stay unchanged.
Board/rules changedSave intended board/settings, then preview and validate again.
Live Board Setup differsSave Board Setup and matching project settings before creating a new preview.
Baseline chain has findingsFix that chain or choose clean routing. Existing errors do not authorize moving it.
199 or more findings of one typeResolve the excessive baseline. Equal totals cannot establish no new findings.
New DRC/connectivity findingsKeep the original. Reduce displacement or scope and validate again; do not disable checks to force approval.
Custom length/skew/pair constraintUse native routing/tuning. Removing the rule does not establish safe timing.
Runtime/worker/CLI unavailableUse matching KiCad 10 native Python and CLI. Restart PCB Editor after installation.
Cancelled, timed out or crashed validationApply remains blocked and the live PCB unchanged. Address the runtime issue or retry a smaller scope.
Export destination existsChoose a new stem or directory; existing files are preserved.
Undo/Redo blockedThe board no longer matches that transaction. Inspect it and use a saved reference if needed; do not force old objects into changed routing.

Object exchanges recover on failure. If a message explicitly says recovery needs inspection, inspect the current board before continuing or saving; do not assume that operation completed.
