Guard signal routes

This synthetic two-layer example uses filled top and bottom GND planes joined by an existing plated ground connection. The dark teal route is the selected signal; light cyan circles are proposed GND vias. No private project or machine paths appear in the capture.

  1. Choose Guard selected routes and an explicit Via net, normally the intended ground. It must differ from all signal nets.
  2. Check exact signal nets, or select PCB tracks and use Use selected PCB tracks. The two scopes are combined. Ctrl+F opens wildcard/fuzzy search with multiple selection.
  3. Set via pitch and track-centre-to-via-centre offset. Choose Both, Left or Right. One-sided placement follows each stored segment's start-to-end direction in the top view; reversing a segment swaps its sides.
  4. Click Preview. The isolated process leaves the interface responsive, with elapsed time and a Cancel planning button. Cancel discards the entire pending result. Inspect both accepted vias and rejection reasons.
  5. Apply only after review. Source, rules and current settings are checked again; changed inputs invalidate the result. Undo/Redo retains the tool's recoverable groups. Run native DRC and review actual return continuity before using the design.

Default previews use a private copy of the saved PCB. Save first, or explicitly enable Include unsaved PCB edits (slower snapshot) in advanced settings. A live snapshot may take longer to serialize. No preview creates PCB copper.

All generated vias are through-vias on the chosen guard net. Straight tracks are supported; arcs/via targets are reported as unsupported/non-straight, not approximated by chords. Target-filled-copper, board edges/cutouts, other-net copper, pad clearance and via keepouts remain guarded. Saved netclass clearance floors cannot be reduced by the planner. Custom/conditional native rules still need DRC.

The filled-target check proves annulus coverage on at least one copper layer only. It does not prove two-layer connection or continuity to the intended ground port. A single-plane native test produced via_dangling warnings; provide the required additional ground connections and run DRC. The tool does not add ground traces or waive these findings.

Guard proposals are bounded to 50,000 and a default 15-second planning budget (explicit maximum 120 seconds). Exceeding a budget yields no partial placement. The table displays the first 1,000 accepted candidates; the full accepted set remains in the canvas and reviewed plan.

{"mode":"Guard selected routes","net_choice":"GND","guard_nets":["/ADC/CLK_P","/ADC/CLK_N"],"guard_tracks":[],"guard_side":"Both","guard_offset":1.0,"spacing":2.5,"diameter":0.6,"drill":0.3,"clearance":0.2,"require_target_zone":true,"guard_budget":50000,"guard_timeout":15}

Use these settings with the existing stitching plan/apply CLI commands below. Net names are exact, track IDs are saved UUIDs, dimensions are mm, and offset is centre-to-centre. Near bends, too-close proposals are rejected. The tool does not establish RF shielding or signal-integrity compliance. Dense public Marble clock-pair trials returned zero legal sites at the tested offsets; inspect exclusions rather than interpreting an empty plan as successful guard coverage.

Workflow

1. Configure geometry and pad scope or target net.

2. Click Preview. The canvas and result table show accepted candidates and rejection reasons. Preview creates no PCB copper.

3. Inspect the result, then Apply to board. A named WayriCAD group contains the committed geometry. Run KiCad DRC before saving or manufacturing.

The optional More → Review placement again command rechecks the board snapshot and prepares the same geometry; it is not required before Apply. More → Clear preview discards unattached candidates. Settings changes invalidate the preview. Board changes require a new preview. Plugin Undo/Redo preserves a recoverable group; reopen the tool to find its existing named groups.

Controls and checks

Choose a PCB net and square or staggered grid. Configure grid spacing, via diameter/drill, copper clearance, edge inset, and uniform or density profiles. Expand Area and exclusion settings to limit the rectangle, use selected-item bounds, or exclude footprints by reference.

By default candidates must fit completely inside filled target-net copper. Missing/unfilled target zones fail explicitly. Other-net copper and via keepouts are always excluded; same-net tracks and footprint envelopes have optional exclusions. The complete via radius plus clearance is checked against conservative obstacle envelopes, and vias remain inside the closed board outline, including cutouts. Too-dense grids and more than 50,000 candidates fail before modifying the board.

Local preview

Primary choices remain visible; detailed dimensions and rejection tables are collapsed until needed. The clean, neutral canvas shows footprint outlines and references, real native pad polygons/rotation, existing copper, and generated geometry. A visible legend, millimetre scale, and coordinate orientation support review; the grid is optional and off by default. The resizable canvas supports wheel zoom at the cursor, drag to pan, double-click to fit, and via picking for coordinates. Pads, existing tracks/vias, zone outlines, and board edges provide context. Candidate copper and drill sizes use board units. Arc tracks currently appear as conservative bounding envelopes; native pads use their effective polygons; the IPC fallback uses supported padstack shapes. The canvas is a review aid, not a replacement for PCB Editor or DRC.

Command line

Use KiCad 10's bundled Python so `pcbnew` is available. List JSON option names and actual project choices with `python -m wayricad_runtime.cli fanout settings --board source.kicad_pcb` (or `stitching settings`). Settings are a JSON object, for example:

{"net_choice":"GND","pattern":"Staggered grid","spacing":2.5,"diameter":0.6,"drill":0.3,"clearance":0.2,"require_target_zone":true}

python -m wayricad_runtime.cli stitching plan --board source.kicad_pcb --settings settings.json --output plan.json --svg preview.svg
python -m wayricad_runtime.cli stitching apply --board source.kicad_pcb --plan plan.json --output routed.kicad_pcb

Plan is read-only and produces reviewable JSON plus an optional standalone local SVG. Apply recomputes and checks the reviewed geometry and board fingerprint, then writes a new `.kicad_pcb` file. It refuses source overwrites, existing destinations, empty plans, and stale or altered candidate geometry. The source remains unchanged.

Compatibility

Native in-memory board tests, file round-trips, and hidden wx frame smoke checks run against KiCad 10. The suite also packages an IPC entry point for forward compatibility; supported geometry depends on the live IPC API. Unsupported capabilities fail explicitly. Live KiCad 11 behavior must be validated against its released runtime.

Resolve an empty or stale plan

  • No filled target copper: fill and save the target-net zones, select the correct net/layer and preview again. The required target-zone test is explicit.
  • Most sites rejected: inspect copper, keepout, outline and footprint exclusions; reduce scope or change legal spacing without relaxing required clearance.
  • Candidate limit exceeded: enlarge spacing or use a smaller area. Generation stops above 50,000 candidates before board changes.
  • Apply disabled after an edit: generate a new Preview. CLI apply also checks source fingerprint and reviewed geometry, and requires a new destination.

Spacing, diameter, drill, clearances, inset and region coordinates are millimetres. Grid style changes candidate positions; it does not prove ground continuity or electrical return-path quality.
