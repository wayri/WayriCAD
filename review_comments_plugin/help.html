Desktop sign-in and compact controls

Choose Sign in in the header, then Sign in browser. Approve the provider's device-code request and return to Review. No CLI installation or token paste is needed for current-source desktop use. GitHub defaults to public repositories plus Discussions write access; the optional private-repository checkbox requests broader repo write access. GitLab needs an OAuth application with device grant enabled; a self-hosted server needs a public client ID in WAYRICAD_REVIEW_GITLAB_CLIENT_ID.

Review keeps its access token in process memory for at most eight hours, or less if the provider token expires sooner. Activity does not extend this time; closing Review loses sign-in. There is no silent renewal or CLI fallback. Expiry blocks reads, sending, uploads and native navigation, clears canvas comment authority and preserves drafts. More → Sign out affects Review only, leaving browser, extension and shared CLI sessions alone. The separate CLI commands still use their legacy gh/glab authentication.

The header has one Light/Dark toggle and an Account action. More holds settings, refresh, reviewer highlights, workflow, sign-out and design visibility. Filters and PCB layers start collapsed. The theme applies to the window and embedded viewer.

Interactive saved-design view

Use Open project/design… to choose a saved PCB or schematic. The file selector includes its paired design and schematic hierarchy files. Navigate independently with pan, zoom, fit and PCB layer controls; switch a PCB to 3D. The current document catalog supplies no component model assets, so 3D uses stand-ins where models are needed. STEP models are outside this integration. The view does not mirror unsaved KiCad edits; edit designs in the main KiCad window.

After Review this file connects the exact saved file and a matching provider refresh succeeds, use Pin comment or Region comment in the 2D view. Markers are local drafts until you explicitly send a message. Provider-read scope and the saved-file SHA-256 govern markers and posting. Selecting a marker focuses its thread; object-linked PCB comments can request navigation in the originating editor. Native schematic selection and native KiCad canvas overlays are unavailable.

The source preview serves its allowlisted viewer assets from memory through a temporary loopback listener. It closes with Review and has no fixed port or background service.

First use

  1. Save and commit the PCB. Launch Review from its PCB Editor.
  2. Settings checks the worktree, full commit and design path. Choose the issue/PR/MR number for Comments and a GitHub Discussion number for Discussions.
  3. Choose Sign in browser and approve the device code at the provider's verification page. Review verifies the account before connecting.
  4. Read cards, click Reply, and use Send message or Ctrl+Enter. People highlights authors; search finds text and design items.
  5. Open in provider opens the authoritative conversation. If no Discussion exists, choose or create one there and enter its number in Settings. The plugin never substitutes an issue for a Discussion.

Threaded engineering discussions

Discussions reads every supported comment/reply page through GraphQL and posts native threaded replies. Replies to replies remain in their top-level Discussion thread. GitLab notes remain under Comments.

Formatted composer and guided workflow

Settings guides you through Provider, Saved design and Conversation. Choose a saved design to detect its Git context. Current-source desktop sign-in opens the provider's device-code page; copy the one-time code if needed. No CLI session is changed. Connected requires a successful provider account check.

The formatting toolbar supports bold, italic, headings, code, lists, tasks, quotes, HTTPS links and tables. Ctrl+B / Ctrl+I / Ctrl+K format selections; Ctrl+Enter sends. Pasted HTML becomes safe Markdown. Preview renders locally without scripts, remote images or automatic link navigation.

Use More → Workflow guide to show the sidebar and drag the horizontal divider to resize the composer. Drafts retain up to 16000 characters; messages allow 4000 including generated links/reply text. Overlong drafts are preserved locally.

Paste images with Ctrl+V, use More → Attach image… or drop PNG/JPEG files onto the composer. Up to four files, each at most 4 MiB and 16 megapixels, are accepted. Each GitLab upload has an approval preview; upload copies become PNG at most 1024 pixels per side. Pending attachments have removable chips and local thumbnails. GitHub attachments use its browser editor.

Find and follow a thread

View thread focuses a message and its replies. All messages returns to the feed without changing your draft or pending reply. Search is scoped to the open thread; combine it with the author chooser and With design context. Clear filters resets search and filters while keeping the thread and draft. People highlights authors without hiding other messages. A removed thread returns to the surviving feed after refresh.

Message actions wrap on narrow cards. The guided sidebar initially folds in small windows; an explicit Workflow choice is retained while the pane is open. More formats expands headings, lists, tasks, quotes, tables and fenced code without crowding the main toolbar. Write and Preview identify the current composer view; the send action identifies a new message or reply. The published-character estimate includes generated reply and image links.

Sync and recovery

Active panes refresh about every eight seconds, backing off to two minutes after failures. Hidden/inactive panes pause. The feed builds at most 80 cards at once and preserves reading position. Participants are observed authors, not online presence or typing indicators.

Local data is an optional cache plus separate unpublished drafts. It never establishes publication. Failed reads stay visibly stale. Conversation changes preserve the outgoing draft and pause editing until the destination is ready. Ambiguous write failures retain text: refresh and inspect the provider before retrying. Writes are never automatically retried.

Saved bytes must match the chosen commit apart from normal LF/CRLF checkout conversion. Exact local-byte hashes protect later operations; unsaved live geometry is outside this review. Native schematic selection, native KiCad canvas overlays, inline PR diff reviews and review summaries are unsupported. GitHub Projects and GitLab boards open in provider UI.

CLI and full documentation

Run python -m review_comments_plugin.cli --help. The post command previews unless --publish is supplied. Set kind: discussion and an existing Discussion number for the GraphQL backend.
