# QuickTherm coupled-board transient screen

`wayricad-therm-transient MODEL.json --output result.json --csv trace.csv --svg temperatures.svg` runs a read-only, lumped thermal RC calculation for exactly four boards in downstream airflow order. The command checks each saved `.kicad_pcb` with KiCad, verifies that each source reference exists, hashes the source bytes before and after solving, and writes the full input model, source hashes, time series, checks and assumptions to JSON. CSV records time in seconds, temperatures in °C, and power/heat flow in W; the SVG plots junction and downstream-air temperatures. The CLI prints SHA-256 hashes of its output files. `--require-checks-pass` returns a nonzero status on FAIL or UNKNOWN. This command is independent of the native steady-state viewport.

Use a reviewed JSON object with `boards` in physical airflow order. Each board needs a unique `name`, `board_path`, `capacity_j_k`, `air_conductance_curve` and at least one `components` entry. A component needs `reference`, `capacity_j_k`, `r_junction_board_k_w` and its actual `fixed_power_w` or an explicit `resistive_loss`. A component can also have `isolated_sink` with measured/assumed sink capacity, junction-to-sink resistance, an airflow conductance curve, and nonempty `isolation_evidence`. Optional `maximum_junction_c` and global `max_local_air_c` produce conditional PASS/FAIL checks. Missing limits yield UNKNOWN. The solver never substitutes a data-sheet maximum power rating for actual dissipation.

An `isolated_sink` requires `contact_kind`. Use `generic_isolated` for an ordinary electrically isolated attachment. Use `metal_drain` for a live-drain path, with `drain_net`, `working_voltage_v` and `insulation_rating_v` in addition to the thermal inputs. The software rejects an entered insulation rating below the declared working voltage. This is an input-consistency check, not verification of dielectric construction, spacing, hi-pot testing or assembly safety.

An optional `fixed_boundary` on a board declares `temperature_c`, finite `contact_r_k_w`, and nonempty `contact_evidence` for a maintained fixture/mount temperature. It contributes explicit signed `fixture_heat_w` to the energy balance. A mounting hole or ground plane alone does not establish this contact.

Supply `inlet_air_c`, `duration_s`, `step_s`, `air_density_kg_m3`, `air_cp_j_kgk`, `fan_curve` as increasing `[flow_m3_s, pressure_pa]` points, `system_k_pa_s2_m6`, and `bypass_fraction`. The fan curve must cover the intersection with `Δp = K Q²`. The model uses `Q_board = Q_fan(1 − bypass)` for all four serial stages; a measured branch-flow network would need a different model. Every `air_conductance_curve` is increasing `[board-channel flow_m3_s, hA_w_k]` points that bracket the operating flow. These curves represent assembled board/sink heat transfer, not free-air CFM. Do not infer them from the fan rating alone.

At each time step, implicit Euler solves each board's board, junction and optional sink nodes. The next board receives the previous board's calculated outlet temperature: `T_out = T_in + Q_air/(ρ Q_board c_p)`. The optional ohmic law is `P(T) = I² R_ref[1 + α(T − T_ref)]`; it is iterated with the thermal solution and rejects negative resistance. It does not represent a MOSFET linear-mode `I·V_DS` law or qualify DC SOA. Energy residual is `P − Q_air − Q_fixture − Σ C ΔT/Δt`; the solver rejects a numerical imbalance above its tolerance.

`status: computed_unqualified` means the numerical model completed, even when a conditional check passes. It does not mean that contacts, dielectric isolation, fan flow, thermal capacities, local air recirculation or component SOA are verified. The model has no spatial copper, via, radiation, package hotspot or airflow-field resolution; use the separate layer-resolved steady model and physical test evidence for those questions. Its downstream-air calculation treats air advection as quasi-steady within each thermal time step, without duct transport delay. Validate the entered network against temperature measurements and time-step refinement before treating a check as engineering evidence.

For a repeated-board demonstration, `examples/thermal-demo-transient.json` uses four named copies of the public demonstration PCB. Its powers, capacities, fan curve and heat-transfer curves are hypothetical and must be replaced for real hardware. Run from the repository root so its relative board paths resolve correctly. Keep private board paths and measurement files out of public reports.
